LANStream and Linux Easy Config (LEC)
======================================

This guide covers Docker installations managed through LEC and the bundled
LANStream-LEC-module-1.0.7.lec package.

It is not a standalone LANStream installer.
Use README.md/manual.md to build and start the service.
The repository includes the .lec module; do not assume a particular .lecdock
deployment preset is also present.

1. Locate the effective configuration
------------------------------------

The location depends on deployment and LANSTREAM_CONFIG_FILE.
The application does not require any particular /home directory.

Suggested host layout:
    /srv/lanstream/config/config.txt
    /srv/lanstream/cache/

Suggested bind mounts:
    /srv/lanstream/config -> /config
    /srv/lanstream/cache  -> /cache

Environment:
    LANSTREAM_CONFIG_FILE=/config/config.txt
    LANSTREAM_CACHE_DIR=/cache

Library paths must refer to container locations.
If /srv/media is mounted at /media, configure /media/Movies.

Historical deployments may bind only config.txt.
The application can read that file, but atomic Settings saves can fail.
Mount the writable parent directory to support web-based saving.

When migrating from paths.txt, explicitly copy roots/profile sections into
config.txt and verify the effective path. Current code does not import paths.txt.

2. What the bundled 1.0.7 module does
------------------------------------

The external LEC module:
- discovers LANStream Docker containers;
- displays runtime information when the local API is accessible;
- opens the web UI and /transcoder-status;
- restarts the container;
- edits roots, exclusions and the access settings it knows;
- translates host/container paths using actual bind mounts;
- uses LEC's privileged configuration/Docker operations when required.

Refresh Status uses HTTP. Rescan Installations repeats Docker discovery and can
request system authorization through LEC's privilege model.
These discovery functions belong to the module, not LANStream itself.

Status requests reuse an in-memory HTTP session.
Authenticated deployments use the shared password or first profile's password.
The application's status API uses its normal session gate.

3. Compatibility with current settings
-------------------------------------

The module predates current quality profiles and integrated NZBDAV.
Its historical Low Bandwidth controls no longer govern current playback quality.

Its render_config reconstructs settings it recognizes.
Saving through this module can remove default_quality and the nzbdav_url,
nzbdav_user, nzbdav_password, nzbdav_root and nzbdav_ram_cache_mb fields.

For current configurations:
- back up the file before saving through the module;
- use LANStream Settings for supported web controls;
- configure NZBDAV directly in the effective file;
- use module status/open/restart without resaving if you need to preserve fields
  the module does not know.

The .lec package is not rebuilt automatically with the documentation.
It is not a complete editor for the current application.

4. Avoid unexpected environment overrides
----------------------------------------

These override matching application settings:
    LANSTREAM_TRANSCODER
    LANSTREAM_USE_MASTER_PASSWORD
    LANSTREAM_PASSWORD

Do not impose conflicting Docker values if the file/UI should manage them.
LANSTREAM_CONFIG_FILE and LANSTREAM_CACHE_DIR locate resources and can remain set.

The external port comes from Docker's mapping.
Included Gunicorn binds to 8080; port= alone does not change it.
Restarting after a file edit does not create a different Docker port mapping.

5. GPU, HDR and caches
---------------------

For VAAPI expose /dev/dri and verify permissions, driver and selected render node.
The VAAPI path keeps video decode, pixel conversion, resizing, supported HDR10/PQ
tone mapping and encoding on the GPU.
Audio, networking and containers still use CPU.

HDR10 transcoding automatically produces SDR BT.709.
Tone mapping is capability-tested separately from HEVC decoding.
A driver can support HEVC Main 10 decoding without HDR processing.
A failed hardware tone-mapping path does not silently fall back to CPU.
Original delivery is unchanged; unsupported Dolby Vision profiles are not converted.

Integrated NZBDAV uses a bounded RAM-only video block cache without rclone.
The /cache directory contains separate graphics derivatives and can use disk.

Check Activity/Playback info for the actual backend and tone-mapping path.
Do not infer successful acceleration solely from transcoder= in the file.

6. Update and restore
---------------------

Preserve configuration and container deployment details.
Rebuild the image and recreate the container with its mounts, ports and GPU.
Restart does not incorporate changed Python files into an old image.

Verify Settings, a local library, any NZBDAV connection and Playback info.
Reload open players after an update.
